## 硬规则（不可静默放宽）

### R3 · 原文不得擅自改写

R3 管的是**权限**，不是**字节**：它禁止的是 **agent 擅自**改写用户的话。用户随时可以授权改写，但那次授权必须是机械的、有界的、可校验的。

skill 只能**追加**新行，绝不重写、润色、重排、去重用户原有内容。

**「追加」这条路径**靠两条独立校验同时保证：

- `bodyExact` —— 原文作为完整字符串出现在写入结果中；
- `originalsPreserved` —— 写入前的每一行仍是写入后行序列的子序列。

副作用：不折叠模板自带的空行（那会删除已有行）。因此 `## 今日的思考` 与首个标记块之间会保留模板原本的空行。

**另两条改写通道不走这两条校验** —— 它们换上一套等价守卫（命中数 + 反向回代 + 块外逐字节不动）。**这是换岗，不是放宽**：

| 通道 | 谁发起 | 性质 |
| --- | --- | --- |
| `--fix-pair` | 默认检测 → 用户逐条点头 | **闸门**（默认流程里的一道确认） |
| `--fix-written` | 用户事后点名要改 | **例外**（用户起意） |

两条通道的共同约束，缺一不可：

1. 只能由**脚本**做字符替换，**绝不由模型产出最终文本** —— 模型一旦动笔，就变成了 R3 要防的「润色」；
2. 修正必须能机械校验（命中数、反向回代）；
3. 默认只报告，改字必须逐条明确同意。

### D5 · 不确定就问

域、锚点、来源、落点**任何一环**拿不准，先问用户，再落盘。不猜、不静默降级、不自行决定。
`#unsorted` 是占位符，不是终点：落占位的同时必须列出候选并当场提问。
除非用户明确要求「全自动、不要问我」，否则本规则不可关闭。

## 设计决策

### D1 · 派生层独立成块

派生层是独立的 `## 今日分类与关联` 区块，位于 `## 今日的思考` 之后、`### 关联笔记` 之前。

被否决的方案：写进 callout。理由：callout 会把 skill 生成的内容注入用户原文区域，违反 R3 的空间边界。

### D2 · 关联通道 2 本阶段关闭

只启用**通道 1**（日记内的 wikilink，即「关联笔记」列的 `[[...]]`）。
通道 2（反向写入被关联笔记，即在目标笔记里登记「哪天的日记提到我」）本阶段关闭。
重新开启需用户显式提出。

### D3 · 默认 dry-run

默认只输出 diff，不落盘。必须显式传 `--write` 才持久化。
理由：写入的是用户的私人日记，误写成本高；diff 是唯一廉价的事前审阅手段。

### D4 · 原文不加时间戳

不在用户原文前追加 `HH:mm` 之类的时间前缀。
捕获时间只出现在两处，格式不同：标记块的 `id` 用紧凑 `HHmm`（`20260916-1547-8c95`，id 是不透明标记不带冒号），派生层索引表的「时间」列用 `HH:MM`（`15:47`）。

## 实现决策

### I1 · 写入通道

用 `obsidian eval` 在 Obsidian 进程内执行 `app.vault.process(file, fn)` 原子替换。

- 弃用 `daily:append`（落到 dataviewjs 之后）。
- 不用 `create ... overwrite`（会丢内容）。
- **不回退到文件系统写入**：Obsidian 未运行时直接中止。实测 `vault.process` 会合并活动缓冲区，plain fs 写入则会覆盖用户未保存的编辑。
- 存在性用 `daily:read`（唯一能触发模板创建的方式），但它输出多一个尾换行，故**字节精确读一律用 `eval` + `app.vault.read()`**。

### I2 · 幂等靠标记块

不比对整文件字节（模板尾随空行等噪声会误判）。逐个读已存在的 `jc:begin`/`jc:end` 块，按内容比对：

- 同内容已存在 → `duplicate`，不写入。
- id 相同但内容不同 → `id-collision`，中止并报错（不覆盖）。

### I3 · id 生成

`<YYYYMMDD>-<HHmm>-<sha1(原文) 前 4 位 hex>`，例如 `20260916-1547-8c95`。哈希取**全内容** sha1，不是「前 4 字节」。
id 的时间段用紧凑 `HHmm`（不带冒号）；「时间」列的展示形式 `HH:MM` 由同一份时间分别格式化得到（`parseTime()` 同时返回 `compact` 与 `display`）。
同一分钟内重复捕获且内容不同时才可能撞车，届时靠 I2 的 `id-collision` 兜住，属 fail-safe。

### I4 · 分类判定必须确定性（已被 T1 / T2 取代）

域由**锚点文件路径**按最长前缀推导，不做语义判断。同一输入必得同一输出。
实现为 `references/registry.json` + `journal_apply.mjs --classify`，而不是让模型自由心证。
只有「域叶子兜底」允许有限语义判断，且必须在 §五 闭集内选值。

→ 分类改成标签后，域/锚点已不存在。见 T1/T2。

### I5 · 注册表机械生成

`registry.json` 由 `tools/build-registry.mjs` 从 `分类词表.md` 解析生成，并在生成时校验：

- 锚点唯一性；
- 每条锚点路径真实存在；
- 域名合法；
- 注册表域与路径映射域一致（不一致会列出「覆盖」供人工确认）；
- 域路径映射与兜底路径真实存在；
- §五 每个域都有叶子定义。

因此 `分类词表.md` 是唯一权威；`taxonomy.md` 与 `registry.json` 都是派生物。

→ 用途已收窄到**只供校对词表**，分类不再读它。见 T6。

### I6 · 候选并列必须外显

`--classify` 返回的 `candidates` 是**全部**并列候选，并带 `ambiguous` / `needsUser`。
汇报里必须把候选集列全——这是锚点选错后唯一的事后纠正线索。

→ 仍成立，但对象从「锚点」变成「标签候选」。

## 分类改用标签（2026-09-18）

### T1 · 分类是标签，不是 `<域>/<锚点>`

旧设计要求分类锚点**必须对应真实存在的笔记文件**，于是「想分类就得先有文件」，还让「分类」与「关联」两件事绞在一起。
改成**多级 Obsidian 标签**后：不需要文件、可层级（`#work/sales`）、可搜索、可进图谱。
派生层「分类」列写**裸标签**（`#work/sales #work/shops`）——**不裹反引号**，裹了 Obsidian 就不认它是标签。
一条捕获可用多个标签（旧设计只允许一个主分类）。

**实测前提**：emoji 可以作为标签段。用一篇秒建秒删的探针笔记跑过 `getFileCache().tags`，`#🐱` `#🎁` `#work/sales` `#门店` `#a/b/c` 全部被认。

### T2 · 词表 = 文档骨架 ∪ 实时库标签

曾一度想把词表完全改成「实时读、不落配置」，因为配置会过期。但用户要**保留已经定稿的 9 域 + 57 锚点**，并要求「一级或二级标签维护到文档」。两者不矛盾，因为两类信息寿命不同：

| 来源 | 内容 | 维护成本 | 何时变 |
| --- | --- | --- | --- |
| `分类词表.md`（骨架） | 一级 9 + 二级 83 = 92 | 人工评审 | 很少 |
| `app.metadataCache`（实时） | 限定目录内实有的标签 | 零 | 随时 |

所以：**骨架落文档（可评审、不漂移），其余一律实时读（不陈旧）**。`--tags` 把两者合起来输出并分组。
写进派生层的裸标签会在下一轮自动进入「实时」那份——分类会自己长出来，不用回头改文档。

### T3 · 词表限定 5 个目录

`00-InBox&FleetNote` / `02-Done` / `09-Note4LLM` / `10-GTD` / `11-Knowledge`。
`101-LiteratureNote` / `102-PermanetNote` 经用户确认**不包括**（实测差异只有一个标签 `#心理结构`）。
其余目录（`04-OnlyWork` / `08-Learning` / `Evernote` / `999-待整理`…）是「其他用途，待整理后整合」，本阶段不纳入。`--scope=` 可覆盖。
**已知代价**：`#朴朴` / `#机器学习` / `#管理` 这些真正好用的主题标签都在被排除的目录里，所以限定目录内现成标签很少（2026-09-20 实测 40 个，随库内标签变动，以 `--tags` 现查为准）。用户明确表示**暂不**只读引入 `04-OnlyWork` / `08-Learning`，因此**以新建标签为主**；`--scope='04-OnlyWork,08-Learning'` 随时可手动查。

### T4 · 只机械剔除三类，不做封闭词表

- `#gtd` / `#gtd/*`：任务状态，不是主题分类（用户明确要求排除）。
- 纯数字：来自 GitHub 链接标题 `· Issue #2672 ·`，Obsidian 会把它们当标签。
- 单字符：代码/链接噪声（`#n` 来自 Jupyter 笔记里的 JSON）。

除此之外**合法即允许**，包括**新建**——这是标签相对文件锚点的核心好处，也是「不放封闭配置」的必然结果。
仍由 `validateTags()` 在写盘前机械校验格式；不合法退出 1，不写盘。

### T5 · 分类仍需用户确认（D5 不变，并用 `--allow-new-tag` 机械强制）

候选由 `suggestTags()` 机械产出（标签名与锚点关键词都会命中），但候选**只是候选**。无候选时提 1–3 个建议，问用户。
定不了用 `#unsorted` 占位（它就是骨架里的一级标签，不另造词）。

关键加固：**词表外的标签必须带 `--allow-new-tag` 才能写**。这把 D5 从「靠自觉」变成「脚本拦得住」：agent 无法在没问过用户的情况下静默扩张词表。

### T6 · `registry.json` 产出「标签骨架 + 校对词表」

`build-registry.mjs` 现在从 `分类词表.md` 机械派生两样东西：

- `tagSkeleton`：`{level1, level2, all, paths}`——分类用。一级 = §二 的域，二级 = §六 锚点 + §五 叶子。不引入新词。
- `anchors`：锚点关键词，`--classify` 的「关键词命中」用它，也是校对词表的来源。（§五 叶子的内容通过 `tagSkeleton.all` 进入代码，不再单独输出 `leaves` —— 2026-09-18 删掉死字段。）

生成器新增的校验当场拓到两个**真冲突**：`#life/健康`、`#family/重要日子`（锚点与同域叶子同名，会产出同一个标签）。处理方式是**删叶子、留锚点**（锚点有真实笔记，更具体）。
锚点的 `path` 不再是合法性前提，只降级成「分类命中时顺手给出的关联列建议链接」。

## 校对（用户输入准确性）

### P1 · 默认只报告，不静默改

`--proofread` 永远只读不写，任何情况下都可以随便跑。修正必须显式 `--fix`，且在写盘时生效。
无发现就直说「未发现可疑之处」，不要为了显得有用而硬凑条目。

### P2 · 两级修正：无损 vs 改字

- **无损**（`--fix=safe`）：`trailing-space` / `repeat-char` / `ascii-case`。只删多余字符或规范大小写，不改语义。
- **改字**（必须显式同意）：`ascii-typo`。这类一旦错就是把对的改成错的。

`--fix=all` 包含改字，所以必须在用户逐条确认后才能用。

### P3 · 判定用词表，不用笔记名

最初拿 1161 个白名单笔记名做词表，在真实文本上 6/6 误报：`代理→管理`、`花了→花费`、`尝试→面试`、`无法→成法`、`网接→网名`、`skill→shell`。
因为笔记名里全是日常词。改用注册表词表后噪声量级下降。
**宁可漏，不能错。**

### P4 · 中文别字检测被实测否定（不做）

拿 155 个词表词做 “同长度、一处替换” 的滑窗匹配，在 2399 篇 / 3.83M 字上给出 9567 条 `cjk-typo`（5.06 条/千字）。

穷举 3070 个不同的错字窗口，在语料中的出现次数分布是：**0 次：0 个**，1-2 次：1125 个，3-10 次：1142 个，11+ 次：803 个。
原因是窗口就是合法长词的子串（`笔记整` 是 `笔记整理` 的子串）。子串包含关系永远无法区分，除非上分词器/词典。

曾试过的两个信号（“错字窗必含生僻字”、“不跨越正确词边界”）能把部分误报降下去，但降不到可用水平。
**结论：删掉。** 一个 5‰ 精度的检查只会训练用户忽略它，而 `--fix=all` 会真的改坏文本。

### P5 · `[[` / `]]` 成对检查被实测否定（不做）

全库 111 处全是误报：

- `[[白话解析] Flink…](url)` —— 这是 markdown 链接文本，文本本身以 `[` 开头；
- `tf.shape(input_tensor)[1]] )` —— Python 代码。

正则分不出这两种。Obsidian 自己会把未闭合的 `[[` 当普通文字渲染，漏报的代价接近零。

### P6 · wikilink 按 Obsidian 的真实规则解析

只比对文件名会产生大量误报（`[[08-Learning/LLM/01-LLM|LLM]]` 是合法路径式链接）。
现在通过 `app.vault.getFiles()` + `app.metadataCache` 建立一个索引：

- 全路径（带/不带 `.md`）
- 文件名（basename）
- frontmatter `aliases`

且 `[[#标题]]` / `[[#^块]]` 是合法的**同文档引用**，只有真正的 `[[]]` 才算空链接。
另：链接区间内的内容不参与拼写检查，否则 `[[02-Done/…]]` 里的 `Done` 会被报成大小写错误。

### P7 · ascii-typo 收紧到“换位或长词”

实测 155 个词表词的编辑距离近邻，约一半是误报：`none→done`、`gate→date`、`rate→date`、`best→Bert`、`team→term`、`spark→sparks`。
因为这些领域词本身就是常见英文词（date、term、diff、sparks、obsidian）。

现在只放行两类：

| 长度 | 允许的距离 | 理由 |
| --- | --- | --- |
| ≥ 7 | Damerau ≤ 2 | 长词很难恰好撞上另一个词 |
| 5-6 | 仅单次相邻换位 | 换位是最常见的错法，substitution 在短词上噪声太大 |

真阳性全部保留：`obsidan→obsidian`、`obsidina→obsidian`、`iceborg→iceberg`、`sprak→spark`。
残余误报约到 `Database→datalake`、`routine→coroutine` 这个量级，作为**建议**可接受。

### P8 · 误报密度是验收指标

改完后的全库密度：

| 类型 | 数量 |
| --- | --- |
| `trailing-space` | 8054（几乎全在旧笔记里，新捕获里很少） |
| `wikilink-missing` | 539 |
| `ascii-case` | 518 |
| `ascii-typo` | 154 |
| `repeat-char` | 74 |
| `highlight-unclosed` | 23 |

扣除旧笔记里既有的行尾空白后为 **0.34 条/千字**（原为 5.06），用户**真实捕获文本上为 0 条**。
任何后续新增检查项，必须把这三档数字重新测一遍并记录。

## 事后改写原文与自检（2026-09-18）

背景：用户事后发现两处错字（「防止便宜」、「系统出设置 bypass」），要求修正。这与 R3
直接冲突，所以不是放宽 R3，而是把同一件事的另一面讲清楚：R3 禁止的是 **agent 擅自改写**，
不禁止 **用户事后指定的字面修正**。因此新增模式沿用写入路径上原本那三条约束。

- **W1 · 改写只能由脚本机械执行。** 模型只给「错→对」对与理由，永不产出最终文本。
- **W2 · 必须用 `--id` 限定块，不允许全库替换。** 同一个词在不同块里含义可能不同：
  「便宜」在 `20260916-1549-0882` 是错字，在 `20260918-1702-fdea` 的「贪小便宜」是真词。
  实测：无 `--id` 的同一对会把真词改成「贪小偏移」。
- **W3 · 反向回代守卫。** 把改后正文逐字反向换回来必须等于改前。右值在原文里本就出现
  过时，字面替换会互相干扰 —— 实测 `便宜→我妈` 被这一守卫拦下。
- **W4 · 块外逐字节不动。** 把块内替换全部推回去后必须正好等于原文。
- **W5 · id 必须重算。** `id = <YYYYMMDD>-<HHmm>-<sha1(正文) 前 4 位>`，正文一变
  等式就断。只重算 id 字符串（含索引行），正文一个字节不动。
- **W6 · 落盘前留字节级备份**，写到 `<vault>/.daily-journal/backup/`（隐藏目录，
  Obsidian 不索引）；并用 `expectBefore` 做乐观并发校验，不一致就不写。
- **V1 · `--verify-ids` 作为常驻自检。** 它把 W5 的等式变成一个可随时跑的命令。

  `--fix` 时序（`finalContent` 确实在 hash 之前赋值）等可能；**当前代码自洽**

  重算后 14/14 全部自洽。
- **M1 · 历史分类迁移也走脚本。** `--migrate-tags` 只改派生层索引行的分类列，
  原文与关联列不动，且每个结果标签仍要过 `validateTags`；混写的行不碰。
- **M2 · 实测：11 个历史分类词全部本来就在骨架内**，只有 `life/HomeLab` 是词表外

### 已知实现坑（新增）

- **P9 · `String.raw` 不处理 `\"`。** 写在 raw 模板里的 `\"` 会原样送进 payload，
  直接语法错误。payload 里的字符串一律用普通双引号（模板限定符是反引号，不冲突）。

## 中文别字由模型识别（2026-09-18）

**问题**：机械校对**查不了中文别字**。`cjk-typo` 已被 P4 实测否决，`ascii-typo` 只管英文词，
而用户实际犯的正是同音字（`便宜`/`漂移`、`系统出`/`系统里`）—— 字符距离法从原理上抓不到。

**用户口径**：「我希望你帮我识别一轮错别字，如果我发现你没有修改，我会提示你的。」

**结论**：把中文别字的**识别**交给模型，但**执行**不放宽 —— 模型输出「错→对」对与理由，
**永不产出最终文本**，替换由脚本做。这与 W1 是同一句话。

- **W7 · 缺的不是权限，是通道。** 采集流程原本没有口子接受模型提的对：`--proofread` 找不到
  中文别字；`--fix=fN` 只认脚本自己找到的条目 id（`applyFixes` 是按 `findings` 的
  `start`/`end` 偏移切片的）；`--replace` 只长在事后的 `--fix-written` 上。
  于是新增 **`--fix-pair='错→对'`**（可逗号分隔多对）。
- **W8 · 守卫一字不省。** 每对必须**命中**，命中 0 次不是「跳过」而是**报错退出** ——
  那说明模型读错了原文；反向回代必须逐字节回到原文；结果写进 `pairReport`。
  顺序上 `--fix-pair` **先于** `--fix`，因为模型读的是**原始文本**，机械修正会先动它。
- **W9 · 明确不动的东西。** `的地得`、口语化写法、生造词、专有名词、中英混排一律不碰 ——
  那是品味，不是错。动了就滑向润色，R3 的口子就是这么开的。
- **W10 · 代价是模型的判断不可复现。** 同一句今天报、明天可能不报。所以机械守卫
  （命中数 + 反向回代）是这套设计唯一的支点，不能省。
- **W11 · 反馈环必须双向。** 用户发现**漏报** → 事后走 `--fix-written`；
  用户发现**误报**（把对的改成错的）→ 更要立刻回滚。**误报比漏报严重。**

连带改动：`SKILL.md` 第 2 步从「脚本查一遍」改为「脚本查格式 + 模型查中文，并成一张清单」；
铁律第 1 条原本写着 `Never … fix typos`，与新功能直接矛盾，已把改字从禁令清单里拿掉并注明
两条合法通道（**R3 这个标题名没动** —— 全库 10 处引用它，改名是另一件事，见「遗留」）。

## skill 自包含（2026-09-18）

**问题**：生成器 `build-registry.mjs` 以前只存在于 vault 的项目文档目录里 —— 那是**唯一**一份，而且不在任何 git 仓库中（vault 不是 git 仓库）。但 `journal_apply.mjs` 依赖它重建 registry。也就是说：**skill 在 git 里，skill 的上游工具不在** —— 改了没历史、回不去。

**改法**：生成器搬进 skill（`<skill>/tools/build-registry.mjs`），随仓库分发。

- **优先级**：`$DJ_REGISTRY_GENERATOR` > skill 自带 > vault 内 `**/tools/build-registry.mjs`（仅兜底）。
- **发现副本就提示**：vault 里若还留着一份，用 skill 自带的，并在 stderr 写明「副本已忽略」。不做静默择一 —— 两份悄悄分叉比只有一份更糟。
- **词表路径改为解析**：生成器原先把 `分类词表.md` 硬绑在自己旁边（`PROJECT_DIR`）。搬进 skill 后那里没有词表，所以改成三级解析：`--taxonomy` > 脚本旁边 > `--vault-root` 下搜（要求唯一，找到多个就报错而不是随便挑）。
- **`--out` 默认值修正**：原来是 `HERE/../../../../../../.pi/registry.json`（按旧 `~/.pi/agent/skills/` 布局算出来的），搬走后会算到无关目录；改成 `<vault-root>/.daily-journal/registry.json`。

## 关联列必须带上对应文件的链接（2026-09-20）

用户口径：「如果日记关联到某个文件，这个文件的链接都放在关联中。」补充：「没有实际文档，关联就没有意义。」

- **A1 · 候选路径只是提示，不是填充项。** `--classify` 给出的别名/锚点路径是在说「库里**可能**
  有对应笔记，核对一下」，不是「就该链它」。真正要链的是**原文里实际点名的实体** ——
  词面命中 ≠ 实体关联。实测反例：2026-09-20 第一条命中了 `#family/🐱`、`#family/🐷`、
  `#life/健康` 三个候选，但它讲的是带娃，三个都链上去就是三条噪声。
- **A2 · 留 `—` 的合法理由是「这条没有对应实体」**，不是「懒得想」。反过来也不为了不留空
  硬链：**文件存在 ≠ 这条内容在讲它**。候选齐全但语义不搭时，`—` 比硬凑的链接好。
- **A3 · 只链真实存在的文件，且由脚本机械保证。** `--links` 的目标按 Obsidian 的解析规则
  （全路径带/不带 `.md`、文件名、frontmatter aliases）解析不到就**退出 7**，dry-run 阶段
  就拦。这与「分类标签可以新建、不需要有文件」不矛盾：**标签是主题，链接是实体**。
- **A4 · 不回溯。** 本规则只管**新捕获**与**用户点名要改的那一条**；已经写完的历史条目与
  索引行一律不动（用户 2026-09-20 明确要求，避免规则变更反向改写旧日记）。

实测：茶叶一条（`#family/🎁`）关联列由 `—` 改为 `[[🎁]]`，指向 `05-personal/🎁.md`。
同一天另三条（`#family`、`#life/HomeLab`）无对应实体，保持 `—`，且按 A4 **不回填**。

## 四处缺陷修复（2026-09-20）

一轮审查报出的四个 P0。共同点：**都是「看起来在工作，实际没在工作」** —— 不报错、不报异常，
只是静默地什么都不做。这类 bug 比崩溃难发现得多，靠的只能是把验收写死在测试里。

- **R1 · `--audit` 搜的是不存在的字符串。** 搜索目标是字面量 `unsorted/-`，而派生层里写的是
  占位标签 `#unsorted`（脚本里的 `PLACEHOLDER_TAG` 常量）。两边从改名标签那天起就对不上，
  `--audit` 永远返回 0 行，却一直显示「正常」。改法：不再匹配整行字面量，而是**拆出分类列
  再按标签比对**（复用 `PLACEHOLDER_TAG`，经 `P.tag` 传进 payload）。
- **R2 · `--migrate-tags` 不认 `--allow-new-tag`。** 写盘路径（读 `args["allow-new-tag"]` 的那
  一支）早就允许「先问用户、用户点头后带旗标放行」，迁移路径却一律 `fail` —— 同一条 D5 规则
  两个入口两种口径。改法：迁移路径对齐写盘路径，`&& !args["allow-new-tag"]`。
- **R3 · 空内容能过五项校验。** `bodyExact` 用的是 `after.indexOf(P.content) >= 0`，
  而 `indexOf("") === 0` —— **空串恒真**，所以空内容能一路混过 pre-write-verify。
  两层都补：CLI 侧 `content.trim() === ""` 直接退出 1（与校对里 `empty` 是 blocking 同一口径），
  payload 侧 `bodyExact` 加 `P.content.length > 0`。
- **R4 · `--fix` 只修每个词的第一次出现。** `seenAscii` 把去重做在**检测循环里**，
  第二次遇到同一个词就 `continue`，于是它压根不会进入 findings —— 一个字错误改一处，
  后面几处漏掉（比不修更坑：看起来改完了）。改法：去重只用于**不重复刷屏**，
  finding 里记下该词**全部**出现的 span（`spans: [...]`），`applyFixes` 展平成 span 后
  统一按位置**倒序**替换。去重与替换彻底解耦，口径与 `--fix-pair` 的全量替换一致。
  顺带：`fixReport` 新增 `replacements`（真实替换处数），不再拿 finding 条数冒充处数。

## `--links` 与反向回代五处缺陷修复（2026-09-20）

同一轮审查报出的另五处。共同点是**边界判定不准**，而不是静默失效：该拦的没拦（R5、R7），
不该拦的拦了（R6），报告里丢信息、报错署错名（R8、R9）。

- **R5 · `--links` 的 `|` 两个方向都没管。** 未转义的 `[[🎁|礼物]]` 会被 markdown 当成列分隔符，
  索引行从 4 列撑成 5 列；而转过义的 `[[🎁\|礼物]]` 又因为没剥掉反斜杠，被当成不存在的文件名拒掉。
  两个方向都要治，且**顺序不能反**：先判「未转义」（前一个字符不是 `\`），再剥 `\| → |` 后切别名 ——
  反过来就分不清「转义过的竖线」和「本来就有两个」。判定与剥转义都收在 `parseWikilinkTargets()`，
  写盘路径与 `--proofread` 共用。
- **R6 · 反向回代用了正序。** 撤销必须按**倒序**逐对回滚：`a→b,b→c` 这种链式对正序撤只会得到
  中间态（`b`），于是干净的字面替换被误判成「右值在原文中也出现过」而拒绝。`--fix-pair` 与
  `--fix-written` 两处同改。**守卫本身不放松** —— 右值真的撞上原文时仍拒。
- **R7 · malformed 闸门太松。** 只在「一个 wikilink 都没有」时报错，于是
  `--links='[[🎁]] 还有裸文字 [[🎁]]'` 会通过，把裸文字写进关联列。补两条：含换行、
  去掉 wikilink 与 `、`/`,`/空白后仍有残留（= 裸文字），各自带 `reason` 与 `detail`。
- **R8 · `pairReport` 丢了命中数。** 只报「替换了什么」，不报「各几次」，用户没法核。现在保留
  每对的 `n` 并新增 `replacements`（总处数），与 `fixReport.replacements` 同口径。
- **R9 · `--map` 报错冒名 `--replace`。** `parseReplaceList()` 的旗标名写死在函数里，
  迁移路径复用时报错就署错名。改成参数化 `flag`（默认 `--replace`，`:1309`）。

## 八处代码缺陷修复（2026-09-20）

同一批审查里剩下的实现缺陷。前四处是「静默失效 / 误报」，后四处是「没说清 / 没拦住」。

- **A1 · `obsidian()` 没有超时，会永久挂死。** `execFileSync` 不设 `timeout`，Obsidian CLI 偶发无响应
  （实测 `--tags` 约 1/60~1/138 概率卡住）就把整个脚本挂住。加 `timeout` + `killSignal: SIGKILL`，
  超时杀子进程、退出 4；阈值可用 `DJ_TIMEOUT_MS` 覆盖（默认 30000）。**这只是止损**：
  Obsidian 为什么偶发无响应仍未查清，超时把「挂死」降级成「可重试的失败」。
  当时把「超时」与「被外部杀掉」混在一条判断里（`e.signal === "SIGKILL"` 也算超时），后来拆开了，见下节。

## obsidian CLI 超时口径统一（2026-09-20）

A1 只做到「不挂死」，落地后暴露出「什么算超时」和「两个 shell 入口没有超时」两件事，一并统一。

- **只有 `ETIMEDOUT` 才算「本脚本超时杀的」。** 改前 `e.code === "ETIMEDOUT" || e.signal === "SIGKILL"`
  都算超时，于是一律提示「Obsidian 侧偶发无响应，重跑即可」。但 Node 按 `killSignal` 超时杀的，和被外部
  （系统回收内存 / Obsidian 崩溃）杀的，在 `e.signal` 上长得一样 —— 把后者说成「偶发抖动」会盖住真实崩溃。
  现在只在 `e.code === "ETIMEDOUT"` 时判超时；只有 signal 时走单独分支，明说**不是超时**并提示看崩溃报告。
  两支都退 4。
- **两个 shell 入口补同一套超时。** `journal_path.sh` / `journal_create.sh` 原本直接 `"${OBSIDIAN_BIN}" ...`，
  没有任何超时，同样会挂死。加 `run_cli`：后台起进程、每 0.1s 轮询，复用同一个 `DJ_TIMEOUT_MS`；超时
  `kill_tree` 后返回 124，调用侧翻译成**退出 5**。为什么不是 4：shell 侧 4 已被「创建后未找到文件」占用，
  JS 侧的 4 是 `journal_apply.mjs` 自己的口径，两个入口各安其位、不互相冒充。
- **`kill_tree` 递归杀整棵树。** 只杀直接子进程的话，被派生的子进程会变孤儿。`pgrep -P` 递归到叶子再
  `kill -9`。
- **JS 侧不需要这套（已核实）。** 一度担心 `execFileSync` 超时只杀 `obsidian` CLI 本身、留下孙进程。
  核实结论是**不会**：`obsidian` 是单进程 socket 客户端 —— `nm -u /opt/homebrew/bin/obsidian` 的 22 个
  未定义符号里 0 个 `fork` / `posix_spawn` / `exec`（对照组 `/bin/bash` 有 6 个），运行期 50Hz 采样 120 次
  也没出现子进程；它只 `socket` / `connect` 到已运行的 Obsidian 应用。shell 侧的 `kill_tree` 因此是
  **防御性**的（CLI 将来若改为 fork 仍安全），不是必需品。
- **`note-not-found` 提示按 `--path` 分流。** 显式 `--path` 指向的文件 payload 只读不建，加 `--write` 也没用；
  之前一律提示「dry-run 不建文件，加 `--write` 会建」，对 `--path` 是错的。现在分两句。

### 实现期实测发现并修掉的 bug

**`## 今日待办` 已存在但 `jt` 标记不存在时，补标记会把下一个标题顶上去。** 原条件

```js
if (body.length > 0 && body[body.length - 1].trim() !== "") ins.push("");
```

只在节体末尾**没有**空行时才补空行。而 `body` 的最后一个元素通常**就是**那个空行（它同时当着下一个 H2 的分隔）—— 空行被「消费」成 `jt:begin` **前**的分隔，`jt:end` 后面一个空行不剩，下一个标题直接顶在 `jt:end` 下一行（MD022）。

修法：`jt:begin` 前保证一个空行，`jt:end` **后**无条件补一个。实测（节在、标记不在、节内还有一行用户手写内容）补出了正确形态，再追加第二条也正确。

实现面**只动 `SKILL.md`**（新增「待办提取：从已有内容里挑待办（提案，不落盘）」一节）；
脚本、模板、既有决策一行未改 —— 机械部分（多行批量、行级判重、五项写入校验、闸门）早就在，
无需改一行代码。

### C9 · 待办提取是提案层，不是写入层

用户没看到、没点头之前，**一个字也不写**。提案只是把候选排成一张表，不碰任何文件。

这条不是新立场，是把既有约束原样接到新入口上：

| 既有约束 | 在提取场景里的含义 |
| --- | --- |
| D3：默认 dry-run，`--write` 才落盘 | 提案比 dry-run 还靠前 —— 连目标行都还没定，谈不上 dry-run |
| R3 / D19：`jc` 原文层不可动 | 原文里那句「明天要交房租」**原封不动留着**，新任务行是 `jt` 层的另一条 |
| D24：日期不猜 | 提案里给建议值并标出源词（「明天」「周四前」），用户确认后才写 |
| D5：拿不准就问 | 宁少勿多 —— 把一句感慨提成待办比漏掉一条更难看，而且用户还得花时间否掉 |
| 待办通道那五项校验 | 提取出的行和直接给的待办**走同一条**通道，不另开小门 |

### 为什么不在脚本里做提取

提取是**语义判断**（哪句是承诺、哪句是感慨，没有机械特征），而且判错了代价由用户承担。
脚本能机械地做的事（造行、补 `➕`、判重、五项校验）已经在 `--kind=todo` 里了。
所以这层切成两段：**agent 只负责提案，脚本只负责落盘**，中间由用户逐条确认。

### 允许改写原句造任务行（但仍要逐条确认）

「明天要交房租」→ `- [ ] 交房租 📅 2026-09-21`，删了「要」、语序也动了。
按 D19，`jt` 层本来就不受 R3 约束，所以机械上允许；但文字毕竟是用户的，
所以回到同一条立场：**转换由你提出、用户点头**，而且要点到**最终文字**那一级，不是只点“要/不要”。

### 来源标记：别名块链接 `[[<笔记名>#^<块 id>|↩]]`（用户确认要标，也确认要能点）

提取出的行默认带一个来源链接，**位置必须放在描述末尾、emoji 字段之前**：

```text
- [ ] 交房租 #family [[2026-09-38w-20#^20260920-2000-a1b2|↩]] ➕ 2026-09-20 📅 2026-09-21
```

**最初写的是注释 `<!-- from:<块 id> -->`**，理由是它不显形、不弄脏任务描述。用户问“能不能用块链接”之后查实两件事，两件都指向别名链接：

1. 块 id 原本只是注释里的字符串，Obsidian 不认 —— 要先给块一个真锚点（C10）。
2. 写在 `<!-- -->` 里的 `[[…]]` **不进链接表**：同一篇里注释内、注释外各放一条指向同一个块锚点，
   metadata cache 只登记了外面那条。所以注释能“活命”（Tasks 字段照解、渲染不显形），但**点不动**。

**别名 `|↩`**：渲染出来只是一个小箭头，但它是个真链接。不写别名就是一长串 `2026-09-38w-20#^20260920-2000-a1b2` 摄在任务描述里。

**带笔记名**，不是光写 `#^id`：`[[#^id]]` 是**同文档**引用，而待办落当天日记、来源块可能在别的日子。

**位置约束（放行尾是错的，而且错得隐蔽）。** Tasks 的字段正则在源码里就是锚定行尾拼出来的：

```js
function Da(n, t) { let e = n + "\uFE0F?"; if (t !== "") e += " *" + t; e += "$"; return new RegExp(e) }
function Sa(n) { return Da(n, "(\\d{4}-\\d{2}-\\d{2})") }   // createdDateRegex = /➕️? *(\d{4}-\d{2}-\d{2})$/
```

解析又是**从右往左反复剥**：

```js
extractField(t, e, r) { let i = t.line.match(e); i !== null && (r(i), t.line = t.line.replace(e, "").trim(), t.matched = !0) }
// 一轮一轮 do…while(t.matched)，依次剥 priority / done / cancelled / due / scheduled / start / created / recurrence / …
// 每轮都要求 line 的**末尾**正好是那个字段，剥掉一个、下一轮再剥下一个
```

所以行尾挂上 `-->` 之后，`📅 …$` 匹配不上，`line.replace` 不会发生，
后续每一轮也都匹配不上 —— **一个字段都剥不下来**，`createdDate` 直接是 `null`。
后果：带这个注释的待办从「今日创建的任务」里消失（`(created …)` 查的就是它；
日记标题里又没有日期，`OR (heading includes …)` 也救不了）。用户就是这么发现的。

放在字段之前则一切正常：日期回到行尾、正常解析；Tasks 渲染描述走 `MarkdownRenderer.render`，
所以那一串 `[[…|↩]]` 只剩一个小箭头、点一下就跳回原文；脚本五项写入校验也照过（`➕` 仍插在 `📅` 之前，实测）。

链接里的 `#` 前面是文件名字符而不是空白，Obsidian 与脚本都不当标签；
脚本的 `wikilink-missing` 只拿 `#` 前的部分对词表，所以够得着、不误报。
**但它只核对笔记名，不核对块 id** —— 块 id 写错就是一个悄悄指向空处的链接（库内实测过：链接与块两个部分都合法才解析得了）。

一句话口径：**行尾必须是字段，注释只能挤在描述里**。行尾任何非字段文字都会让**全部**日期字段解析失败 ——
库里就躺着一条现存例子：`- [ ] fzy 和 fzf 的区别 ➕ 2026-06-25 】`。

收益与局限：它证明不了提取对不对，只能回答「这条待办是哪句话来的」。

## 块锚点：让 `[[笔记#^id]]` 跳回那段思考（2026-09-20，已实现）

### C10 · 锚点钉在正文最后一行的末尾

**用户问的**：待办的出处标记能不能直接用 Obsidian 块链接，点一下跳回来源想法？

**当时不行**：`jc` 块的 id 只是注释里的一个字符串，Obsidian 不认。要用块链接，得先给块一个真锚点。

**Obsidian 的锚点规则**（从 `Obsidian.app/Contents/Resources/obsidian.asar` 里挖出来的两条注册规则）：

```js
// 整行只有 ^id
var t = /^\^([a-zA-Z0-9\-]+)$/, n = /\s/;
// 段落以 ^id 开头、后接行尾/换行/空行
var i = /^\^([a-zA-Z0-9\-]+)(?=$|\n$|\n\n)/;
```

定位器要求 `^` 前面是空白。库里本来就有同型的例子：`> ⏱ 2024-05-26 21:07:33 ^23723810-32-7520-7566`。

**锚点放哪**：三个位置里选了「正文最后一行末尾」。

| 放哪 | 正文动没动 | 代价 |
| --- | --- | --- |
| **正文最后一行末尾（选它）** | 动了 | 「正文」的切法多一条：尾部 `^<本块 id>` 不算正文 |
| `jc:end` 标记行尾 | 没动 | 14 处精确匹配串要放宽，且注释行认不认没实测过 |
| `jc:end` 之后单起一行 | 没动 | 锚点在区外，`--fix-written` 换 id 时会留下过期锚点 —— 直接破「块外一个字节都不改」 |

**锚点值就是块 id**：一个 token 两用，不用多养一个短锚点，也不可能对不上。

**不变量**：正文的切法改死一条 —— 标记之后、尾部 `^<本块 id>` 之前。`sha1(正文)` 的定义本身没变。
锚点落在区**内**，所以 `--fix-written` 重算 id 时它跟着搬家。回推证明要拿锚点的**原值**还原，只记位置会让「锚点值不对、hash 对」那种情况误判成块外被牵连。
另外，同一段思考第二次捕获必须仍判成 duplicate —— 比对正文时也得先剥锚点，否则每捕一次就多写一个块。

**顺带查实的一件事**：写在 HTML 注释里的 `[[…]]` **不进链接表**（实测：同一篇里注释里放一条、外面放一条，指向同一个块锚点，metadata cache 只登记了外面那条）。
所以「出处放注释里」能活命（Tasks 字段照解、渲染不显形），但是**点不动**；要能点，链接就必须露在任务描述里。

## 传输失真：`code=` 入参每 8192 字节会吃掉多字节字符（2026-09-20，已修）

### C11 · 传输完整性 fail-closed，不做「尽力而为」

**事故**：给 `02-Done/2026-09-38w-18.md` 补锚点那次 `--write`，把 `### 关联笔记` 里一段 dataviewjs 模板代码的
「设**置**脚本在库中的相对路径」写成了「设???脚本…」——一个字变三个 U+FFFD。文件 mtime 正是写入时刻，此后没人碰过。
日记是本 skill 唯一不可重建的数据，**静默写坏是这里最坏的失败**，所以按事故处理、不留「大概没事」。

**定位（三层排除）**：

1. 磁盘备份里 `expectBefore` 那半段是干净的 → 不是读坏，也不是 Obsidian 写坏；
2. 同一份载荷只回 `{len, sum}`、不写盘：`after` 那半段稳定出现 3 个 U+FFFD，**逐字节可复现**；
3. 边界扫描（`{"k":"A"*PAD + "置"*1200}` 逐个 PAD 试）：坏窗口固定在 code 字节的 **8192 的整数倍**附近，
   间隔正好 8192；把载荷挪一下（加个短 ASCII 前缀）坏处就消失。

**规则**：

- 只有**多字节字符**会被切断（3 个合法 UTF-8 字节 → 3 个 U+FFFD）；纯 ASCII 载荷 30000 字符反复送，**零差异**。
- 只发生在 **Node → Obsidian 的 `code=` 入参**这一路：回程 stdout 测到 240 KB 中文无损。
- 只有**长**参数会被碰到（窗口在第 8192 字节处）；几 KB 以内的 `path=` / `file=` 参数不受影响。
- CLI 是 `Obsidian.app/Contents/MacOS/obsidian-cli`，`eval` 不接受 stdin，所以绕不开 argv。

**修法两道，前一道是根因，后一道是保险**：

1. `escapeNonAsciiForCli()`：进 `code=` 之前把非 ASCII 全写成 `\uXXXX`。语义等价（字符串字面量、正则、模板串、注释都吃这个转义），
   入参因此是**纯 ASCII**，没有多字节序列可被切断。实测：把当初坏掉的那份载荷原样重放，
   不转义时 `after` 破，转义后 `after` 与 `expectBefore` 双绿——即使入参因此变长、路过更多窗口，照样无损。
2. `FIXWRITTEN_PAYLOAD` 的 `afterLen`/`afterSum`（Node 侧 31 进制滚动和）：Obsidian 收到载荷后
   **落盘前先自查**，对不上就返回 `transport-corrupt`、**一个字都不写**；写后再回读自查一遍（`readBackExact` + `readBackSumOk`）。

**为什么不只靠第 2 道**：校验和能保证永不静默写坏，但会把「CLI 以后又变了」变成每次写入都失败；
ASCII 转义让它根本不发生。**光比字符串是不够的**——两边一起被改坏时字符串照样相等。

**不变量**：任何落盘路径都必须能证明「Obsidian 收到的字节 = Node 算出的字节」，
且「回读的字节 = 打算写的字节」；证不出来就中止，不报成功。
改写类六个落盘点（`--fix-written` / `--repair-text` / `--migrate-tags` / `--link-block-ids` / `--add-anchors` / `--verify-ids --write`）
都走 `writeNoteInObsidian()` 一处实现；捕获通道（思考 / 待办）不经过它 —— 它由 payload 内的 `commit()` 落盘，
所以那道自查放在 `WRITE_PAYLOAD` 入口，指纹域由 Node 侧 `captureStampSrc()` 与 payload 里的 `stampSrc`
逐字对应（字段顺序改一处就得同时改另一处）。

> 初版只给 `writeNoteInObsidian()` 加了自查，捕获通道只剩 `readBackExact` 字符串相等 ——
> 而本条自己写着「光比字符串不够」，等于**最有价值的那条路径**（承载用户逐字原文、用得最多）反而没兜住。
> 2026-09-20 补上，两侧同口径。

**怎么自查这个包**（换机器/升级 CLI 后能用）：先跑离线自检 `node tools/payload-selftest.mjs`（不碰库、不需要 Obsidian 在运行，
假 `app` 替掉 Obsidian；锚点、幂等、撞 id、两条通道的载荷指纹、ASCII 转义都在里面）。
它必须跟着脚本走、同仓同版本 —— 初版把它放在 `/tmp`，结果改指纹域时它退化成 19/1 而没人知道。
换机器/升级 CLI 后想再验一次真库：造一份中文正文 > 8 KB 的夹具笔记，跑一次 `--add-anchors --write`，
再逐字符比对「原文 + 只追加锚点」，验完删掉夹具（连 `.daily-journal/backup/` 里的 `.bak` 一起删）。

**上游**：这是 `obsidian` CLI 的缺陷，值得报给 Obsidian。`--repair-text` 就是为「写下去之后才发现被改坏」这类事留的通道。

### `--repair-text` · 块外文本的机械修复通道

**为什么需要**：`--fix-written` 只管 `jc:begin`/`jc:end` 之间的正文，可这次坏的地方在 `### 关联笔记` 的 dataviewjs 模板代码里，
块外。修它只有两条路：绕开脚本手改（硬规则 5 不许），或者加一条受闸的通道。

**闸门**（缺一条就拒绝，一个字不写）：

| 闸 | 口径 |
| --- | --- |
| 指定文件 | 必须给 `--path`；只修这一个文件，不接受「全库扫」 |
| 命中唯一 | 每对必须**恰好命中一次**；命中 0 次或 >1 次都拒（宁少勿多，想限定就给更长的上下文） |
| 不许碰块内 | 命中落在任何 `jc` 块体内 → 拒，并要求改用 `--fix-written`（正文有 id 一致性约束） |
| 不含换行 | 只修一行之内的字面错字，`--replace` 两边都不许有换行 |
| 反向回代 | 把替换倒序撤销必须**逐字节**回到原文 |
| 只此一处 | 把命中处（左值版/右值版）都挖成同一个哨兵后，两侧必须完全相等 |
| dry-run | 缺省只打印那一行改前改后；`--write` 才落盘，先写 `.daily-journal/backup/`，走 `writeNoteInObsidian()` |

**分工**：块内正文 → `--fix-written --id=… --replace='错→对'`（会连带重算 id）；块外文本 → `--repair-text`。

**本次修复**：`02-Done/2026-09-38w-18.md` 行 119 的三个 U+FFFD 换回「置」。
验证方式不是「看着对」：拿**补锚点之前**那份备份对照，修完的文件与它只差 6 个锚点，即「干净原文 + 仅锚点」。

## 派生层的「块 id」列改成块链接（2026-09-20，已实现）

用户要求：分类的块 id 能不能也加上链接。之前那一列是不透明的 opaque id（`` `20260920-1025-e95b` ``），
看得见、点不动，要找那段思考还得自己拿 id 去搜。

### C12 · 「块 id」列写成别名块链接

**形态**：`[[<笔记名>#^<块 id>\|<块 id>]]`，与待办出处标记（C9）同一个口径：

```markdown
| 时间 | 块 id | 分类 | 关联 |
| --- | --- | --- | --- |
| 10:25 | [[2026-09-38w-20#^20260920-1025-e95b\|20260920-1025-e95b]] | #family | — |
```

| 选项 | 定案 | 理由 |
| --- | --- | --- |
| 别名留 id 文本 | 选它 | 列里仍然看得见 id（日记是纯文本可读的语料，不是只给人点）；不写别名 Obsidian 渲染成「笔记名 > 块 id」，这一列被撑得很长 |
| 别名用 `↩`（同 C9 的待办标记） | 没选 | 整个列变成一棃箭头，扫一眼读不出哪行对应哪个 id |
| 裸 `[[#^id]]` 同文档引用 | 没选 | 行被剪到别的笔记里就哑了（同 C9 实测） |
| 续用反引号代码段 | 没选 | 代码段里的 `[[…]]` 不进链接表，点不动 |

**为什么不能裹反引号**：链接里再裹反引号就是代码段，不是链接 —— 与分类列裸标签那条同一个道理。

**引入的新隐患：列里出现 `\|`。** 「关联」列早就有这个问题（已记在 SKILL.md 步 5），现在「块 id」列也有了。
所以**解析侧全部改成按未转义的 `|` 拆列**：

- Node 侧 `splitUnescapedPipes()`：`splitIndexRow()` 与新增的 `remapIndexRowIds()` 都用它；
  同时 `splitIndexRow()` 不再硬要求“反引号裹着”，改成 `indexCellId()` 同时认旧（反引号）与新（块链接）两种形态。
- Obsidian 侧 `AUDIT_PAYLOAD` 内联一份同口径的 `splitRowCells()`（载荷不能调 Node 函数，也不得含反引号/`${`）。

**那是个静默坑**，值得单记一笔：`--audit` 原来是 `lines[j].split("|")` + `cells[3]` 取分类列。
块 id 列一旦出现 `\|`，列序号整体后移一位，`cells[3]` 拿到的就不是分类列，那些行**被默默丢掉** ——
不报错，只是结果少几行，看上去像「本来就没有 #unsorted」。实测（库内真实笔记）：

```text
老写法 split("|")[3]      = "20260920-1025-e95b]] "   ← 不是分类列
新 splitRowCells[3]       = " #family "                 ← 还是分类列
同一份 AUDIT_PAYLOAD、tag=#family、2026-09-16..20：
  老写法 命中 0 行（静默丢行）      新写法 命中 2 行
```

**换 id 时只动那一格**（`remapIndexRowIds()`）：形态无关，格内那串 id 出现两次（`#^id` 与别名）一次换掉；
同一行其余字节一个不动（不重排版 —— 不重排，回代证明才守得住）。调用方是 `--fix-written` 与 `--verify-ids --write` 两个方向。

**边界**：只认索引行。`## 今日待办` 里用户自己的 `` [[…#^id|↩]] `` 不被牵连（那是另一层、另一件事）。
**已存缺口（未修）**：待办出处链接不会跟着重算，块 id 变了它就指向空处；要不要自动跟改另议。

### C13 · 历史笔记用 `--link-block-ids` 回填，不手改

新捕获自动写链接形态，但**历史笔记里还是反引号**。形态迁移不回去改，那些行就永远点不动，所以给一条回填通道：

```bash
scripts/journal_apply.mjs --link-block-ids         # dry-run
scripts/journal_apply.mjs --link-block-ids --write
```

**三条约束**（与 `--migrate-tags` 同构）：

| 约束 | 口径 |
| --- | --- |
| 只动一格 | 只改索引行的块 id 格；行内其余字节、原文、其余三列都不动（整文件回代必须逐字节回到原文） |
| 块必须真在 | 块不在本文件里 → 报 `block-missing`，**不写、不跨文件补** |
| 块必须有锚点 | 没尾巴锚点链接就跳不过去 → 报 `anchor-missing`，叫你**先跑 `--add-anchors`**；这里不代劳补锚点（两件事分开，各自可核） |

默认 dry-run，逐行报 `文件:行 old → new`；`--write` 先写 `.daily-journal/backup/`，走 `writeNoteInObsidian()`（含并发编辑检测与传输自查）。
已经是链接形态的行直接跳过，所以重跑幂等（报 `nothing-to-do`）。`end 标记缺失` 的半个块也跳过并报原因，不拿迁移通道去修。

**本次回填**：4 篇笔记 21 行（`2026-09-38w-{16,17,18,20}.md`），全部有锚点，零跳过。
跟备份 diff：**只有那 21 行不同**，其余零变化。

## 待办提取默认随捕获落盘（2026-09-21）

用户口径：「修改下 skill，写日志的时候，如果有待办，也一起写，除非我明确说不写。」

C9 把提取一律定成**提案层**（摆候选 → `然后停下来等` → 点到最终文字才写）。这次按**触发点**分两档，
**只动捕获那一档**；回溯那一档原样保留 C9 的全部口径。

- **E1 · 捕获路径默认写入。** 捕获思考时顺手扫到的明确承诺，**不再等确认**，与那段思考同批落进 `jt` 层
  （`--kind=todo`，同一条通道、同一套闸门）。理由：`jt` 层的写入成本本来就低 —— 不受 R3 约束、
  没有 `id = sha1(正文)` 的等式、用户随时可勾选/改期/删；而每次捕获都摆一张表让他逐条点头，
  换到的是「用户替 agent 干分拣」。
- **E2 · 回溯路径仍是提案层。** 「把今天的待办挑出来」翻的是**旧内容**，改动面比当次捕获大，
  用户没点名要写就一个字不写。C9 那张提案表、那句「然后停下来等」都只属于这一档。
- **E3 · 默认写入不放宽 D5 / D24。** 两条例外照旧，且各自都有机械守卫：
  **拿不准的不提**（D5）—— 少了「写前确认」这道人工闸，「宁少勿多」从此是**唯一**的准入门槛，一个字也不能松；
  **相对日期仍要问**（D24）—— `task-date-relative` 本来就阻断落盘，所以默认写入**不会**顺手把日期也替你定了，
  遇到 `明天` 必然多一次往返（这是特性，不是漏网）。
- **E4 · opt-out 是一句话，不是配置。** 用户说「这次别记待办」「不用提取」，就跳过并回报一句。
  不新增旗标、不落配置：这是**口径**，不是模式。

**代价（记下来，别当没发生）**：少了「用户看到最终文字」这道人工闸，误提的待办会**真的落进日记**。
兜底三条：① 只提明确承诺，拿不准不提；② `--kind=todo` 的阻断项复检（相对时间 / 错状态符 / 非任务行）原样在；
③ 回报时**逐条列出写入的行**，用户一眼能核、一行能删 —— `jt` 层本来就是用户拥有的可变层。

**实现面：零代码改动。** 机械部分（多行批量、行级判重、五项写入校验、阻断项复检）早就在 `--kind=todo` 里，
这次动的只有 `SKILL.md`（工作流第 7 步、硬规则 1 里 `jt` 层那句话、「待办提取」整节的默认口径）
与两份决策记录。因此**不新增代码验收项** —— 能被机械验的都是既有能力，已在 #61–79 与 #85 验过。
这条的验收就是下一条含待办的捕获：按新口径直接写进去、回报里逐条列出、`--verify-ids` 仍自洽。
