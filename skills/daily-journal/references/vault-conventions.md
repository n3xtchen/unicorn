# 库约定与 CLI 实测行为

本文件记录实现所依赖的**已实测**事实。改动脚本前先读这里，避免重新踩坑。

## 库

| 项 | 值 |
| --- | --- |
| vault 名 | `nextlink`（默认值；可用 `$DJ_VAULT` 覆盖，`--vault=` 优先级更高） |
| vault 根 | **不写死**。运行时向 Obsidian 取 `app.vault.adapter.basePath` —— 各人机器不同，写死就不通用了 |
| CLI | `PATH` 里的 `obsidian`；可用 `$DJ_OBSIDIAN_BIN` 指定，**不写死** |
| 目录 | iCloud 同步目录，文件名与内容含中文与 emoji |

## 日记命名（来源：`.obsidian/daily-notes.json`）

```json
{ "folder": "02-Done", "template": "998-template/journal", "format": "YYYY-MM-WW\\w-DD" }
```

- `format` 等价 shell `date "+%G-%Vw-%d"` → 例如 `2026-09-38w-16.md`（ISO 年-月-第38周-日）。
- 路径**一律向 Obsidian 索取**（`daily:path`），不自行拼接。

## 日记模板结构

`998-template/journal` 的区块顺序：

```text
![[IMPORTANT]]
## 马上要完成的          <- tasks 查询块
## 今天要完成的          <- tasks 查询块
## 今日完成的任务        <- tasks 查询块 ×2
## 今日创建的任务        <- tasks 查询块
## 今日的思考            <- L0 原文层（jc 块，只追加）
## 今日待办              <- L1 待办层（jt 区，任务行；模板里可留空，缺了由 skill 创建）
   (5 个空行)
### 关联笔记            <- dataviewjs，加载 Scripts/x.js，targetHeading = YYYY-MM-DD
```

`Scripts/x.js` 扫描 `09-Note4LLM/` 下标题**恰好等于** `YYYY-MM-DD` 的笔记。因此「关联笔记」是库内既有机制，**本 skill 永不触碰**。

## 四层结构

| 层 | 位置 | 谁维护 | 规则 |
| --- | --- | --- | --- |
| L0 原文层 | `## 今日的思考` 内、`jc` 块中 | 用户 | **只追加，不得擅自改写**（R3） |
| L1 待办层 | `## 今日待办` 内、`jt` 区中 | 用户 + skill 追加 | 可变：勾选、改期、拖动、删除全归用户；**不受 R3 约束**（D19） |
| L2 派生层 | `## 今日分类与关联` | skill | 可重建、可手改 |
| 关联层 | `### 关联笔记` (dataviewjs) | 库既有机制 | 永不触碰 |

固定节序：**思考 → 待办 → 派生 → 关联**。

- 派生层：`## 今日的思考` 之后、`### 关联笔记` 之前。不存在时由 skill 创建。
- 待办层：`## 今日的思考` 之后、派生层（或 `### 关联笔记`）之前。不存在时由 skill 创建。
- 新 `jc` 块落在 `## 今日的思考` 内，**在待办节之前**（不是全文件末尾）。
- 待办节被拖到派生层之后时，视为**不存在**：退回改动前的行为（不报错、不写入）。

## 待办行语法契约（对齐库内 obsidian-tasks-plugin）

`.obsidian/plugins/obsidian-tasks-plugin/data.json`：`taskFormat: "tasksPluginEmoji"`、`setCreatedDate: true`。

```text
- [ ] <描述> [#gtd/next-action|#gtd/wait-for] [🔺|⏫|🔼|🔽] [[[<笔记名>#^<块 id>|↩]]] [➕ YYYY-MM-DD] [🛫] [⏳] [📅] [🔁 <rule>]
```

四条硬规则：

1. 一行一个 checkbox；顶格行必须是 `- [ ]`，缩进行当子项。
2. 子项缩进用 **Tab 或 4 空格**，同一个块内不混用。
3. 字段顺序固定：标签 → 优先级 → `➕` → `🛫` → `⏳` → `📅` → `🔁` → `✅`/`❌`。乱序会让 `#gtd/wait-for` 分组与日期查询漏掉这一行。
4. 日期一律写绝对 `YYYY-MM-DD`（D5 / D24）。

第 4 条之后的口径还管着**行尾**：**行尾只能是一个 emoji 字段**。
Tasks 的字段正则全部锚定行尾、从右往左反复剥，行尾挂上任何非字段文字（`】`、`-->`、逗号），
**全部**日期字段就都解析不出来（库里现存例子：`- [ ] fzy 和 fzf 的区别 ➕ 2026-06-25 】`）。
所以出处链接只能挤在描述里（`[[<笔记名>#^<块 id>|↩]]`，别名 `↩` 是可点的小箭头，
同样受这条约束——放在 emoji 字段之前）。

状态符只认四种：空格（待办）、`x`（完成）、`/`（进行中）、`-`（取消）。

**`➕ <笔记日期>` 是 skill 唯一可自动补的字段**（D22，默认开，`--no-task-add-created` 关）。
取的是**笔记日期**而不是脚本运行日：补记昨天的日记时，运行日是错的那一天，而错值的行仍然完全合法，五项校验全绿 —— 没有任何机械守卫拦得住。

主题分类写在**行内标签**（如 `#family`），与 `#gtd/*` 是两个口径：前者是主题，后者是任务状态。
行内主题标签走**同一套词表与同一道 D5 闸门**（骨架 ∪ 库内实有，词表外要 `--allow-new-tag`）；
`#gtd/*` 不进去，另由 `task-tag-unknown` 校对。扫描时另剔除两类噪声：纯数字
（Obsidian 自己就不把 `#123` 当标签）与单字符。
待办**不进索引表**（`splitIndexRow()` 硬要求 4 列、时间列 `HH:MM`、块 id 列能认出 id，不动，D21），也不新增 tasks 查询块（视图层不变，D23）。

## 标记块协议

```markdown
<!-- jc:begin id=20260916-1547-8c95 -->

<用户原文，逐字节> ^20260916-1547-8c95

<!-- jc:end id=20260916-1547-8c95 -->
```

- **块尾锚点**：正文最后一行的末尾追加一个空格加 `^<块 id>`。于是 `[[笔记名#^20260916-1547-8c95]]` 能跳到这段思考。
  Obsidian 只给落在一段真文本里的锚点注册块（整行只有 `^id`、或跟在别的字后面都行），
  **HTML 注释行不算** —— 实测写在 `<!-- -->` 里的 `[[…]]` 不进链接表，点不动。所以锚点不能挂在 `jc:end` 上。
- **锚点不算正文**：算 sha1、比对幂等之前一律先剥掉。不剥，锚点里的 id 会自指进 hash，
  而同一段思考第二次捕获会被当成新块重复写。
- **旧块没有锚点**：任何校验都照过；`--fix-written` / `--verify-ids --write` 只更新已有锚点的值，不替旧块补。
- `id = <YYYYMMDD>-<HHmm>-<sha1(原文) 前 4 位 hex>`。id 里的时间用**紧凑形式** `1547`（id 是不透明标记，不带冒号）。
- **块 id 列写成块链接**：`[[<笔记名>#^<块 id>\|<块 id>]]`，别名就是 id 文本本身。
  点一下跳回那段思考；不写别名 Obsidian 会渲染成「笔记名 > 块 id」，这一列被撑得很长，所以别名必须写。
  笔记名不能省 —— `[[#^id]]` 是同文档引用，行被剪到别的笔记里就哑了（与待办出处标记同口径）。
  别名里的 `|` 要逃成 `\|`（同关联列）。历史笔记里裹反引号的旧形态（`` `id` ``）用 `--link-block-ids` 迁移。
- 派生层「时间」列用 **`HH:MM`**（如 `15:47`），与 id 的紧凑形式不同（见 [[02-设计与写入协议]] 落盘示例）。
- 幂等靠**逐块比对原文内容**（先剥掉尾部锚点，再按行 rstrip、整体 trim 后比较），不靠整文件字节。
- `id` 撞车且内容不同 → 报 `id-collision` 并中止，绝不覆盖。

派生索引表：

```markdown
## 今日分类与关联

<!-- jc:index:begin -->
| 时间 | 块 id | 分类 | 关联 |
|---|---|---|---|
| 15:47 | [[2026-09-38w-16#^20260916-1547-8c95\|20260916-1547-8c95]] | #learn/spark | [[<关联笔记>]]、[[<另一篇>]] |
<!-- jc:index:end -->
```

新行插在 `jc:index:end` 之前（按时间升序累积）。「关联」为空写 `—`。
**孤儿 index 标记**（只有 begin 或只有 end）→ 报 `orphan-index-markers` 中止。

待办区（无 id，**整节一对标记**）：

```markdown
## 今日待办

<!-- jt:begin -->
- [ ] 交房租 #gtd/next-action ➕ 2026-09-19 📅 2026-09-25
- [ ] 等快递 #gtd/wait-for ➕ 2026-09-19
<!-- jt:end -->
```

- 整节只有**一对**标记、**没有 id**（D20）。新行插在 `jt:end` 之前。
- 幂等口径：**行文本 rstrip 后全等**（扫全区）。不做整文件字节比较。
- 同一批里**全部**已存在 → `status: duplicate`（退出 0，文件字节不变）；
  **部分**重复 → 报 `task-line-duplicate` 退出 6，**不静默跳过重复行**。
- 标记数不等于 1，或标记不在 `## 今日待办` 节内 → 报 `orphan-jt-markers` 退出 6。
- `jt` 区不参与 `--verify-ids`（`jt:` 不匹配 `jc:` 正则），勾选待办不会让 id 自检报错（D19）。

## 写入闸门

`app.vault.process()` 落盘前必须先通过六项校验，任一不通过即中止、不写：

| 校验 | 含义 |
| --- | --- |
| `marksBalanced` | `jc:begin` 数 == `jc:end` 数 |
| `oneBlockAdded` | 恰好新增 1 个块 |
| `hasNewBlock` | 新 id 的 begin 标记在结果中 |
| `bodyExact` | **原文以完整字符串出现在结果中**（R3 不得擅自改写） |
| `originalsPreserved` | 写入前的每一行，都是写入后行序列的子序列（不删行、不换序） |
| `blockInSection` | 新块的两端标记都落在 `## 今日的思考` 内 —— 到它之前不能再冒任何 H2（D25） |

前五项查的是**内容守恒**（有没有弄坏已有东西），第六项查的是**位置正确**。少了第六项，
待办节插进来源后，新 `jc` 块会被拼到待办节**后面**，而前五项全绿（实测复现过）。

待办通道同源但不同名，五项：`jtPairPresent` / `inSection` / `linesInserted` / `regionClean` / `originalsPreserved`。

落盘后再 `app.vault.read()` 回读，必须与预期结果字节一致（`readBackExact`）。

**回读比对之外还有一道载荷指纹**：Node 算 `len` + 31 进制滚动和，Obsidian 收到后**落盘前先自查**，
对不上就返回 `transport-corrupt`、一个字都不写。两条通道同口径：改写类六个通道走 `writeNoteInObsidian()`，
捕获通道（思考 / 待办）在 `WRITE_PAYLOAD` 入口自查（指纹域见 `captureStampSrc()`）。
只比字符串是不够的 —— 两边一起被改坏时字符串照样相等。

## CLI 实测行为（重要）

`obsidian` CLI 通过 IPC 与运行中的 Obsidian 通信。

| 事实 | 说明 |
| --- | --- |
| 必须 Obsidian 在运行 | CLI 依赖 IPC；未运行时**中止**，不回退到文件系统 |
| 主进程检测 | `pgrep -f "MacOS/Obsidian$"` —— 精确匹配主进程，排除 helper |
| `eval code=<js>` | 输出前缀为 `=>` 加一个空格；**不支持顶层 `return`**，必须包在 async IIFE 里 |
| `eval` 可用 API | `app.vault.getAbstractFileByPath` / `read` / `process` / `getMarkdownFiles`、`app.workspace.*` |
| `daily:path` | 只返回路径，不创建文件 |
| `daily:read` | **会创建**缺失的日记（套模板、解析 `{{date:...}}`）；输出**多加一个尾换行**，不是字节精确读 |
| `daily:append` | **禁用** —— 会追加到 dataviewjs 之后 |
| `code=` 不转义 `\n` | 传参时必须给真实换行 |
| 参数传递 | Node 侧用 `execFileSync(bin, [args])` 数组传参，绕开 shell 引号问题 |
