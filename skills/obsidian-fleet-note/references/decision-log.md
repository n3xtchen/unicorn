# Skill 创建与迭代记录

本文档记录 `obsidian-fleet-note` 的设计决策，供后续迭代捕获笔记流程时参考；它不是用户 FleetNote 的内容。

## 2026-09-01：初始目标

目标是把一个主题及其来源整理成一篇独立、可检索、可追溯的 FleetNote，写入指定 Inbox，并避免影响已有笔记。

## 设计决策一：单主题、单新文件

一次捕获默认只创建一篇独立 Markdown 笔记。不得覆盖同名文件，也不得顺手重命名、移动、整理或编辑其他已有笔记。

## 设计决策二：来源与正文分离

正文 `## 内容` 是经过整理的最终理解；引用、来源元数据和原文放在 `## 引用`，不放进 frontmatter。引用必须区分原文、转述和个人思路，不能编造作者、日期、路径、commit、行号或链接。

## 设计决策三：保留对齐过程但不复制整段对话

只有发生实质歧义、纠正或约定变化时才添加 `## 对齐记录`。记录最终约定及其影响，不复制隐藏推理或整段无关对话。用户纠正的内容优先进入最终正文。

## 设计决策四：引用必须可定位

Git 来源优先使用固定 commit SHA；本地文档记录路径和章节/页码；网页记录标题、URL、访问时间和章节。引用 prompt 或可见回复时，必须从实际 JSONL 记录中确认 session path、entry ID 和物理行号，不能凭消息序号猜测。

## 设计决策五：只添加有意义的出链

`## 关联` 只放有意义的 outbound links，不通过修改目标笔记制造 backlinks。没有可靠关联时省略该节。

## 后续迭代规则

- 新增来源类型时保持统一的 `S1`、`S2` 引用模型；
- 用户对刚创建笔记的修正只更新目标笔记并追加对齐记录；
- 若来源不可验证，保留不确定性或标记 `待补充`，不以推测填空；
- 任何新自动化都不得突破“只创建一个新文件、不碰已有笔记”的边界。
