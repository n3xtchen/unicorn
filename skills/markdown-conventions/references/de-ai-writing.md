# 去 AI 化表述规范

适用范围：本 skill 处理的**所有中文正文**——文档、笔记、报告、汇报、说明、评审意见。不限 Obsidian、不限 vault、不限仓库，任何目录下由你写出的中文都适用。只管表述，不管事实与口径（事实边界按各项目自己的规范）。

## 1. 总原则

AI 腔的共同特征是**先声明结构、再填内容**：先告诉你"要讲三件事"，再用对偶句包装判断，最后用空词收尾。去 AI 化的做法是反过来：直接写事实和结论，让结构自己显现。

- 一段一个意思，第一句就进入具体内容；
- 判断和事实分开写，不含并成对偶句；
- 不解释"我为什么写这段"，只写读者需要的信息；
- 拿不准就写"待确认"，不用模糊词兜底。

## 2. 六类要避免的句式

### 2.1 计数式开篇

用"三件事""三条主线""两个方面"当段落骨架，是最容易被认出来的模板痕迹。读者自己数得出来，不需要提前告知。

| 原文 | 改后 |
| --- | --- |
| 本周三条主线：完成 A、升级 B、建立 C。 | 本周主要在做基础工作：把 A 梳理清楚，定下 B 的格式，理顺 C 的归属。 |
| 本周三件事：A、B、C。 | 本周的进展集中在基础工作：把 A 梳理了一遍，把 B 定下来，也理顺了 C。 |

如果确实需要一个总起句，用一句状态判断（"本周的进展集中在基础工作"）而不是计数外壳。

### 2.2 「不在……而是……」「不是……而是……」

对偶句读起来像金句，但中文工作汇报里很少这么说话，而且会把两个意思压成一句，反而难读。多数情况拆成陈述句。

| 原文 | 改后 |
| --- | --- |
| 本周的重点不在新增功能，而是把几件基础的事讲清楚。 | 本周主要在做基础工作：把线上链路梳理清楚，定下模型制品格式，理顺过程字节的归属。 |
| 生产读的不是交付原字节而是被改写的部署副本。 | 生产实际读取的是被改写的部署副本，交付原字节没有被直接消费。 |
| 发布规范的核心不是目录约定，而是把三类信息分开。 | 发布规范里真正起作用的是把三类信息分开。 |
| 难点不在技术，而在于是否给它留出时间。 | 它的难处在于是否愿意给它留出时间。 |

### 2.3 问答式总结

把"回答了哪些问题 / 还有哪些没回答"当作章节收尾，是模板感最强的一种写法。改成"做到了什么、没做到什么"。

| 原文 | 改后 |
| --- | --- |
| 梳理和规范回答了三个问题：A、B、C。至于 X、Y，目前还没有答案。 | 这几项工作把 A、B、C 落到了书面上。X、Y 目前还没有定论。 |
| 本周主要解决三个问题…… | 本周处理的是…… |

### 2.4 并列段落同一句式

连续三段以上用同一种句型开头（例如都是「X 需要 Y。」），读者会明显感到机械。让每段直接从具体内容切入，主题句的位置和形状都要有变化。

| 原文 | 改后 |
| --- | --- |
| 观测应当作为兜底结构的一部分。多层兜底如果没有日志…… | 多层兜底如果没有日志……观测能力适合和兜底层级一起设计。 |
| 交付合同需要版本演进机制。字段可选、旧字段保留期…… | 字段可选、旧字段保留期……这类约定，能让升级留出迁移窗口。 |
| 发布规范的关键是把三类信息分开：…… | 发布规范里真正起作用的是把三类信息分开：…… |

### 2.5 写作动机与元话语

解释"我为什么写这段""这份材料给谁看"的句子，对读者没有信息量，一律删掉。

| 原文 | 改后 |
| --- | --- |
| 目的：给下游模块和组内同学一个统一的交付规格。 | （删除，直接写规格） |
| 标题写成「交付合同的最终格式（可分享版）」 | 标题写成「交付合同的最终格式」 |
| 本节简要介绍发布目录…… | （删除，直接写发布目录） |

### 2.6 空词与无数据结论

| 避免 | 替代 |
| --- | --- |
| 形成闭环、持续赋能业务 | 具体动作 + 可检查的结果 |
| 全面沉淀组织能力、统一抓手 | 写出沉淀物名称与落点 |
| 取得显著突破 | 给出数据或对照口径 |
| 仍需持续关注 | 写明待确认项和责任人 |

## 3. 推荐做法

- **先判断后事实**：第一句给状态或结论，后面用事实支撑；不要先声明"要讲几件事"。
- **信息形态对齐，句式不雷同**：并列项都是动作或都是结论，但开头不要用同一句型。
- **状态要落在词上**：已完成用"完成、通过、发布"，设计阶段用"完成设计"，计划用"计划、建议"，未验证用"待验证、方向性估算"。
- **写清适用范围**：指标、收益、验证结论都要带范围或对照，避免被读成全量或线上结果。
- **收尾写具体判断**：不要用"综上""小结"另起一段复述前文。

## 4. 落笔后自检

与 lint 并列执行：

```bash
rg -n '三件事|三条主线|两个方面|共同点|综上|小结|赋能|抓手|闭环|沉淀能力|不在.{0,20}而是|不是.{0,25}而是|并非|回答了.{0,6}问题|目的：|（可分享版）' <file.md>
```

命中后逐条判断能否改成直接陈述；LLM 提示等内部备注不在此列。
