**备选口径**（本项目不采用）：如果用户想保留 H1，改配置一次全清，比逐个删 H1 划算：

```yaml
    front_matter_title: ""
```

采用备选后，本 skill 第 9 条同步改为"保留 H1、frontmatter 不再写 title"，并回填 166 个文件。

未拍板前，遇到"既有文档已有 H1"不要顺手删——只在新写的内容上执行默认口径。

## D2 · MD033 与表格内换行

**状态：暂不放开；需要 `<br>` 时让 MD033 报错，届时再单独处理。**

Markdown 表格单元格没有跨渲染器稳定的原生换行语法。需要换行时有以下选项：

1. **推荐：把内容移到表格外**。表格只保留摘要，详细说明放在表格后面的列表或段落中，兼容性最好。
2. **推荐：拆成多行记录**。如果每行有独立语义，就拆成多行；不要把多个事实挤在同一个单元格里。
3. **可选：使用 `<br>`**。显示效果最稳定，但需要在配置中允许 `br`，否则 MD033 会报错：

   ```yaml
     MD033:
       allowed_elements: [br]
   ```

   ```markdown
   | 多行 | 第一行<br>第二行 |
   ```

4. **不推荐：单元格内用两个行尾空格换行**。MD009 允许两个行尾空格，但不同 Markdown 渲染器对表格内硬换行的处理不稳定，且容易被格式化工具清掉。
5. **不推荐：单元格内嵌套列表或段落**。各渲染器表现不一致，也容易触发 MD032/MD033；内容复杂时改用表格外的列表。

当前执行口径：**不修改 markdownlint 配置，也不把 `br` 加入白名单**。需要 `<br>` 时保留报错，等实际场景出现后再决定采用表格外说明、拆行，还是放开白名单。

mermaid 围栏中的 `<br/>` 不受 MD033 影响，因为围栏内不解析 HTML。

## D3 · MD060 与 prettier 的真实关系（已定论，勿再传错）

**状态：已定论。**

曾误判为"prettier 对齐表格 → MD060 → `--fix` 修不了 → 格式化后必然复发"。实测推翻了它：

- prettier 的对齐产物 lint **通过**（0 error）。
- MD060 要求的是"同一张表内风格一致"，不是"禁止填充"。
- 真正诱因：**在已对齐的表格里手改单元格内容而不重新对齐**，正文行竖线与表头错位。
- `markdownlint-cli2 --fix` 确实没有 MD060 修复器（`--fix` 后 29 处 MD060 一处未动），所以修表格要靠 prettier 或手工统一。

执行口径：手写一律 compact；改完表格单元格必须重跑 `mdlint.sh` 或 prettier。

## D6 · 编辑即格式化（默认开启）

**状态：已定论（2026-09-20，用户口径）。**

用户口径：「markdown skill 默认编辑时都进行格式化，除非我明确不改。」

执行口径：

- 本次编辑只要触及某个 `.md`，就**默认**把该文件修到机械层 0 error，**不必再问**「只修格式还是顺手修内容」。
- 只有用户当轮明确说「不要动格式」时才跳过；也不要自行扩大范围到本次没改的文件。
- 机械层（自动）与内容层（按 D1/D2 不动、要改先问）的划分见 SKILL.md「范围」。
- 收尾报告：「改前 → 改后」的 error 数 + 剩下哪几条 + 为什么留。

实测证据：`05-personal/🎁.md`（2026-09-20）在此口径下由 194 → 3。改的是整表归一 compact、展开 4 处硬制表符、给列表前后补空行；剩下 `MD041 ×1`、`MD033 ×2`，均为内容层，按 D1/D2 保留。

### D6 附 · MD060 与中文表格（实测，勿再凭直觉）

MD060 判定的是「同一张表内风格一致」，且**按显示宽度比较竖线位置**（中文按 2 列宽）。三种最小用例（同一份 `cjk` 数据，只改填充方式）：

| 写法 | MD060 |
| --- | --- |
| 整表 compact（`\| a \| b \|`） | 通过 |
| 按**显示宽度**填充对齐 | 通过 |
| 按**字符数**填充对齐（中文只算 1） | 报错，且被判定成 compact 风格后报 "extra space to the left" |

`05-personal/🎁.md` 那 184 条 MD060 不是「中文没法对齐」，而是**手工填充本身不一致**（同一列有的按显示宽度、有的按字符数）。

执行口径：**中文表格一律写 compact**（SKILL.md 第 1 条）；存量表要修就整表归一 compact，不要手对齐。
